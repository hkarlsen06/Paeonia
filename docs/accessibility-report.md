# Accessibility evidence and release gate

Last reviewed 1 November 2026. Work starts at `fc08741b`. No label is verified, and this development audit is not legal certification. App Store answers and the public statement are prepared, not published.

## Criteria and scope

Apple requires every common task to work with a feature before claiming its label, separately for each supported device. This includes first launch, third-party sign-in, purchases, settings, widgets and notification actions. Use the current [overview and linked evaluation criteria](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/overview-of-accessibility-nutrition-labels) when reviewing the device-specific answers below.

The current implementation has four main tabs and ten games. `MainTab.questions` names the Chats tab internally. Existing native semantics, local-first storage, private nickname resolution, hidden-answer rules, adaptive layouts and Reduce Motion behavior were inspected before extending them.

Us > Accessibility now controls optional visible tools. Extra controls and media alternatives each offer Automatic or Always show. Automatic uses SwiftUI's [assistive-technology environment](https://developer.apple.com/documentation/swiftui/environmentvalues/accessibilityenabled), including before sign-in. The preferences hide optional buttons and fields, preserve drafts and stored descriptions, and keep validation and failed-save recovery available. Labels, board semantics, text size, contrast and Reduce Motion remain active. Verification of this presentation change is pending; earlier recorded feature journeys describe the prior visible presentation.

Our quality goals exceed Apple's label requirements: comfortable AX5 layouts, 44-point custom targets, efficient navigation, stable focus, accessible creation, durable drafts and correction after sharing. Apple does not list the last two as separate label requirements. Neither automated audits nor the labels establish legal compliance.

## Task-by-feature matrix

`S` means source inspected; `J` means a direct simulator journey without assistive technology; `A` means a completed automated audit, with its pass or findings retained; `U` means a passing completed automated journey; `R` means passing assertions recovered from the incomplete AX5 run; `P` means remaining runtime verification. Both `U` and `R` describe only the named assertions, not whole workflows. A code never means complete feature support. Scope and size come from the record above or linked historical result. Every row remains pending for actual assistive technology and separately for iPad.

For each row cover ready, empty, loading, offline, failure, disabled, completed and interrupted states where applicable. Record any inapplicable state with a reason. Check English and Norwegian Bokmal, long names, AX5, Bold Text, Reduce Motion, Increase Contrast with Reduce Transparency and grayscale. Check focus after presentation, error, live update and dismissal. Locked answers, secret targets, unfinished creature parts and private nickname sources must never enter speech, braille, trees or announcements.

Widget review and automated regressions close the revision-identity, durable-overlay, cache-failure and stale-publication cases within their tested scope. These software landing blockers are closed by automated evidence. Complete media journeys with assistive technology remain pending.

Freehand meaning is not recognized. A labeled canvas, shape geometry or a description alone does not establish accessible participation. Neither drawing game expires the artist's turn, and Draw & Guess guesses have no deadline. Its competitive +2/+1 bonuses still use 15/30 seconds after the first live stroke or replay-ready clue. Description reading consumes that time without pause or extension. Together omits the bonus. Common blind participation and competitive fairness remain unresolved blockers, not equivalent access through another activity.

No prerecorded tutorial video, movie, spoken game cutscene or authored dialogue was found. Voice messages and answers are actual audio content. Synthesized game sounds accompany visible state. Re-evaluate content and label applicability when the inventory changes.
