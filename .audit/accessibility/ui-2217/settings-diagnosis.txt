What the documentation and executable proof establish

Apple's User Defaults guide says command-line -key value pairs enter
NSArgumentDomain and take priority over application and global preferences:
https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/UserDefaults/AboutPreferenceDomains/AboutPreferenceDomains.html

Running the retained user-defaults-argument-proof.swift with the same key and
L argument confirms that an isolated defaults suite still reads L after a
stored AX5 value is written. It changes no global or product preference.
This proves Foundation preference priority, not UIKit or audit internals.

The Xcode 27.1 XCUIApplication SDK header says launch arguments remain in
effect for the current launch session. Its accessibility-audit API records
issues unless the handler returns true. The test handler continues returning
false for every issue. XCUIAccessibilityAuditTypes.h defines the raw values
used in the dataset, including dynamicType 65536 and textClipped 131072.

Apple describes the Dynamic Type audit as checking adjustment to system font
preferences, and clipping checks as examining larger Dynamic Type sizes:
https://developer.apple.com/documentation/accessibility/performing-accessibility-audits-for-your-app
